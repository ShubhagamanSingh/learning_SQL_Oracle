# Classwork: Account Debit Transaction

**Original date:** 18 December 2021

The exercise creates five accounts and attempts to debit 2000 while retaining a minimum balance of 500.

## 1. Create the table

```sql
CREATE TABLE accounts (
    account_id VARCHAR2(10)
        CONSTRAINT accounts_pk PRIMARY KEY
        CONSTRAINT accounts_id_ck CHECK (account_id LIKE 'AC%'),
    account_name VARCHAR2(20) NOT NULL,
    balance NUMBER(10,2)
        CONSTRAINT accounts_balance_ck CHECK (balance >= 0)
);
```

## 2. Insert the original sample data

```sql
INSERT INTO accounts VALUES ('AC001', 'Ajay',   5000);
INSERT INTO accounts VALUES ('AC002', 'Robert', 10000);
INSERT INTO accounts VALUES ('AC003', 'Mita',   5000);
INSERT INTO accounts VALUES ('AC004', 'Sunita', 15000);
INSERT INTO accounts VALUES ('AC005', 'Melba',  10000);
COMMIT;
```

The raw transcript shows `AC001` being entered twice, but its final result contains only one row. With a primary key, the second identical insert would raise `ORA-00001`; this cleaned script inserts it once.

## 3. Correct debit block

```sql
SET SERVEROUTPUT ON;

DECLARE
    requested_account accounts.account_id%TYPE := '&account_id';
    debit_amount      CONSTANT NUMBER := 2000;
    minimum_balance   CONSTANT NUMBER := 500;
    current_balance   accounts.balance%TYPE;
BEGIN
    SELECT balance
    INTO current_balance
    FROM accounts
    WHERE account_id = requested_account
    FOR UPDATE;

    IF current_balance - debit_amount >= minimum_balance THEN
        UPDATE accounts
        SET balance = balance - debit_amount
        WHERE account_id = requested_account;

        COMMIT;
        DBMS_OUTPUT.PUT_LINE('Account debited successfully.');
    ELSE
        ROLLBACK;
        DBMS_OUTPUT.PUT_LINE('Insufficient balance.');
    END IF;
EXCEPTION
    WHEN NO_DATA_FOUND THEN
        ROLLBACK;
        DBMS_OUTPUT.PUT_LINE('Account not found.');
END;
/
```

### Why this version is safer

- `%TYPE` follows the table's column types.
- `FOR UPDATE` locks the selected account row until commit or rollback, preventing two sessions from spending the same balance concurrently.
- The update subtracts from the column directly.
- Both success and failure have an explicit transaction outcome.
- A missing account produces a friendly message.

For real financial systems, use a ledger, immutable transaction records, audited procedures, authorization, and stronger concurrency and error handling; a mutable balance-only table is a learning simplification.
